# 公共资料硬链接隔离测试

日期：2026-11-17；平台：Windows x64，Microsandbox 0.7.11。

## 实现

- 仅公共资料源启用硬链接例外，按字节复制为独立文件；私有导入和 Docker 原目录挂载保持严格校验。
- 完成的公共副本再次检查无硬链接、符号链接或嵌套挂载，之后只读挂入 VM。
- 复制时检查文件标识、大小和修改时间，拒绝复制过程中变化的文件。
- 固定用户指定根目录别名的真实路径，兼容旧盘符迁移入口；目录内的符号链接/junction 继续禁止，运行中更换根目录指向会报错。
- 同次启动对相同公共目录只扫描一次，每位访客的私有目录仍分别验证；不跨启动或工具调用缓存检查结果。

文件测试确认两个源硬链接在副本中具有不同文件标识、链接计数均为 1；改写或删除副本，原件及另一个副本不变。原件后续变化也不会改动已有副本。

真实 VM 测试确认 Python 对公共硬链接副本的改写、追加、删除、重命名均被拒绝；复制到自己的 `/work` 后可修改、删除，宿主原件保持不变。访客私有源中的硬链接以及公共目录中的 junction 继续拒绝。另验证了私有文件 CRUD、跨访客隔离、网络/凭据隔离、30 秒暂停和 10 分钟停止对应的状态转换、重启后保留文件；生命周期转换使用受控时钟驱动真实 VM，没有等待完整 10 分钟。A2A 工具派发使用真实 Agent runtime 和测试模型适配器。

所有破坏性隔离操作只针对临时合成文件和测试 VM，未改写用户公共资料。

## 复现

```powershell
pnpm exec vitest run tests/sandbox-files.spec.ts tests/isolation.spec.ts tests/workspace-read.spec.ts
$env:A2A_MICROSANDBOX_TEST='1'
# 可选：复用现有 runtime 缓存
$env:A2A_MSB_TEST_RUNTIME='C:\Users\huangjuhua-desktop\.a2a\sandbox-runtime'
pnpm exec vitest run tests/microsandbox.integration.spec.ts
```

公共资料仍受每次复制 512 MiB、100000 项的限制。本机当前选定的目录只做了元数据统计（排除 node_modules），约 21.4 GiB、71451 项、4 个硬链接文件；没有为测试复制整个用户资料目录。服务启动与访客首次读取时的资料复制是两个阶段，后者仍需要合适的目录或调整容量策略。
