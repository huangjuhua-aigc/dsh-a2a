# 真实飞书日历预约测试

测试日期：2026-11-17（Asia/Shanghai）。

## 环境与范围

使用本机已启动的 Portal、实际 `my-agent`（DeepSeek `deepseek-flash`）、独立受邀访客和主人已授权的真实飞书主日历。访客通过 A2A 调用技能发送消息；没有使用模型固定回复或日历接口替身。Agent 监听本机网卡，测试客户端使用只监听 loopback 的临时转发端口。

本报告对应飞书的本地链路测试，不包含公网 Relay。Google 的真实授权和预约在随后独立完成，见 [Google 实测报告](test-report-google-calendar-live.md)。两个渠道的共同保护逻辑另由自动化测试验证。

## 发现并修复的问题

飞书忙闲接口在查询范围内没有忙碌日程时，实测返回 HTTP 200、`code: 0`、`data: {}`。官方 CLI 的接口 schema 也将 `freebusy_list` 标为可选。原实现要求该字段必须是数组，因此把正常空闲误报为 `Cannot verify calendar availability`。

现在只在明确成功、且 `data` 为对象时，将缺省列表视为空闲。缺少 `data`、错误码、HTTP 失败、错误列表类型和无效时间仍拒绝预约。测试替身也已改为模拟真实的空列表省略行为。

额外直接调用服务端工具边界验证：重复确认同一 booking ID 仍返回已确认，没有新增事件；另一访客身份查询或确认该 booking ID 均被拒绝；同一时间的新提案因冲突被拒绝。这些检查与上面的真实模型对话分别记录。
